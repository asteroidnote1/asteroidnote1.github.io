Paired beats unpaired: the same 4-point difference needs about 500 cases, not 1,447 per group

Every number in this article comes from synthetic planning scenarios. None comes from a real model, product or benchmark. In this article, one point means 0.01, so a 4-point difference is 0.04.

Your baseline A passes about 0.80 of your eval. You have a candidate B. The smallest difference that matters to you is 4 points, from 0.80 to 0.84.

Before you write or label a single new case, you need to know how many cases it takes to see that difference reliably.

There are two honest answers:

  • 1,447 cases per group if A's and B's scores are compared as independent groups.
  • 489 cases by the planning formula if you run A and B on the same cases and analyze the pairs. You need 517 if you decide with the exact test (see Catch 2).

Few teams build two separate test sets. The common version of this mistake is running A and B on the same cases and then comparing the two scores as if they were independent. That throws away the same information.

On the same cases, the paired analysis needs about a third as many: 1,447 / 489 ≈ 2.96. If you really did build two separate test sets, that would be 2,894 cases to write, about 5.9 times as many (2,894 / 489).

The difference and the error rates are the same in both designs. The rest of this article explains where the gap in sample size comes from and when it shrinks. It also shows how to reproduce the planning numbers yourself.

The settings

Both answers use the same settings:

  • Two-sided α = 0.05. If A and B are truly the same, you raise a false alarm (declare a difference, better or worse) at most 0.05 of the time.
  • Power = 0.80. If B is truly 4 points better, you detect it 4 times out of 5.
  • The difference: baseline 0.80, target 0.84, a difference of 0.04 (0.84 − 0.80).

The unpaired answer: 1,447 per group

The standard formula for comparing two proportions answers "how many cases per group?" This article uses the pooled-variance version (Fleiss, no continuity correction). For 0.80 versus 0.84, it gives 1,447 cases per group.

There are two ways to end up here:

  • You compare the two scores as independent on 1,447 shared cases.
  • You build two separate test sets, one for A and one for B. That is 2 × 1,447 = 2,894 cases.

Other sources may give slightly different numbers, depending on the formula:

Formula Cases per group
Pooled (used here) 1,447
Unpooled variance 1,445
Baseline-variance shortcut 1,570

The shortcut plugs in the baseline variance twice, which makes it easy to compute by hand. In simulation, it delivered power of about 0.830 instead of the target 0.80. The pooled n delivered 0.798.

So here the shortcut errs on the safe side. It asks for 123 more cases per group than needed (1,570 − 1,447).

The paired answer: 489

Now run A and B on the same cases and keep the per-case results. Each case lands in one of four cells:

B passes B fails
A passes n11 (both pass) n10 (regression)
A fails n01 (improvement) n00 (both fail)

Only the two off-diagonal cells say anything about whether B beats A:

  • n10: A passed and B failed (a regression).
  • n01: A failed and B passed (an improvement).

A case that both systems pass tells you the case is easy. A case that both fail tells you it is hard. Neither tells you which system is better.

Discordance is the share of cases in those two cells. To compute it, count the cases where exactly one of A and B passes, and divide by n.

Suppose discordance is 0.10:

  • 0.03 of cases regress, so p10 = 0.03.
  • 0.07 of cases improve, so p01 = 0.07.
  • The net difference is 0.07 − 0.03 = 0.04.

The paired sample-size formula (Connor 1987, Sample size for testing differences in proportions for the paired-sample design) then gives 489 cases.

You build those 489 cases once and run them through both A and B.

Why pairing wins: the arithmetic

Sample size is driven by the per-case variance of the difference you are estimating.

Unpaired. Each group contributes its own binomial variance:

0.80 × 0.20 + 0.84 × 0.16 = 0.16 + 0.1344 = 0.2944

Paired. Only discordant cases vary in the difference:

discordance − difference² = 0.10 − 0.04² = 0.10 − 0.0016 = 0.0984

The variance ratio is 0.2944 / 0.0984 ≈ 2.99. The ratio of the planned sizes per group is 1,447 / 489 ≈ 2.96.

The two ratios are close but not identical. The reason is that the planning formulas also use the variance expected under "no difference," and that variance differs slightly between the two designs.

The intuition. Your cases differ in difficulty. An unpaired analysis has to treat that case-to-case variation as noise. A paired analysis cancels it, because each case serves as its own control. When A and B agree on most cases, as prompt and model variants usually do, you know the difference more precisely than either score.

Catch 1: discordance does all the work

The paired advantage depends entirely on discordance, and discordance depends on your change.

Imagine that A's and B's outcomes were unrelated on every case. Discordance would then be:

0.80 × (1 − 0.84) + (1 − 0.80) × 0.84 = 0.128 + 0.168 = 0.296

Plug that into the paired variance: 0.296 − 0.0016 = 0.2944. That is exactly the unpaired value. At that discordance, pairing gains nothing. Pairing helps only because, in practice, A and B tend to pass and fail the same cases.

A second scenario shows the advantage shrinking. Take 0.80 → 0.85 with discordance 0.20 (p10 = 0.075, p01 = 0.125):

  • paired: 626 cases
  • unpaired: 906 per group, or 1,812 in total on two separate sets

The ratio per group is about 1.45 (906 / 626). Pairing is still worth it, but the advantage is nowhere near three.

Where to get a discordance estimate. Look at your own earlier comparisons on the same eval set. In a synthetic prompt-tweak example, discordance was 0.080.

Some reasoning about what to expect (inference, not measured):

  • A model swap can flip many cases in both directions, which raises discordance.
  • A narrow prompt fix tends to flip fewer cases.

If you are unsure, plan with the highest discordance you consider plausible. Higher discordance gives a larger n, which is the safe side.

Catch 2: the exact test is conservative

The usual test for paired pass/fail data is McNemar's (McNemar 1947, Note on the sampling error of the difference between correlated proportions or percentages). Its exact version conditions on the discordant pairs and uses the binomial distribution.

The exact test is discrete, so in practice it rejects less often than its nominal α. At n = 200 with discordance 0.10, its actual false alarm rate is 0.029, not 0.05.

The cost is power. At the Connor n of 489, the exact McNemar test has:

  • power 0.775 by exact enumeration;
  • power 0.775 by simulation (1,000,000 replicates), with a Monte Carlo standard error of 0.0004.

The two agree to within the simulation's standard error. Enumeration has no simulation error, so treat it as the reference.

The asymptotic (large-sample) McNemar test reaches about 0.81 at the same n.

What to do. If you will decide with the exact test, add a cushion. Search upward from n = 489 with shipornot power-mcnemar --method enum until power reaches 0.80. For this scenario, the smallest such n is 517, with exact power 0.800. That is 28 more cases (517 − 489).

Reproduce it yourself

1. The planning formulas in plain Python. This needs no dependencies.

from statistics import NormalDist
from math import sqrt, ceil

z_a = NormalDist().inv_cdf(1 - 0.05 / 2)   # two-sided alpha 0.05
z_b = NormalDist().inv_cdf(0.80)           # power 0.80

p1, p2 = 0.80, 0.84
delta = p2 - p1                            # difference
pbar = (p1 + p2) / 2
var_alt = p1 * (1 - p1) + p2 * (1 - p2)

n_pooled   = ceil((z_a * sqrt(2 * pbar * (1 - pbar)) + z_b * sqrt(var_alt)) ** 2 / delta ** 2)
n_simple   = ceil((z_a + z_b) ** 2 * var_alt / delta ** 2)
n_baseline = ceil((z_a + z_b) ** 2 * 2 * p1 * (1 - p1) / delta ** 2)

p_disc, delta = 0.10, 0.04                 # discordance, smallest difference that matters
n_paired = ceil((z_a * sqrt(p_disc) + z_b * sqrt(p_disc - delta ** 2)) ** 2 / delta ** 2)

print(n_pooled, n_simple, n_baseline, n_paired)   # expected: 1447 1445 1570 489

The first three numbers are cases per group. The last is the total number of paired cases.

2. The same numbers with shipornot 0.1.0 (free, MIT: https://github.com/asteroidnote1/shipornot):

shipornot n-unpaired 0.80 0.84                          # per-group n: 1447
shipornot n-paired 0.10 0.04 --check-exact              # 489
shipornot power-mcnemar --method enum 489 0.03 0.07     # about 0.775
shipornot power-mcnemar --method enum 517 0.03 0.07     # about 0.800
shipornot power-mcnemar --method sim --sims 1000000 --seed 20261118 489 0.03 0.07   # about 0.775

Add --json to any of these for machine-readable output. Run any command with --help to see its options.

3. Exact power of the exact McNemar test, by enumeration. This needs numpy and scipy.

import numpy as np
from scipy.stats import binom

n, p10, p01, alpha = 489, 0.03, 0.07, 0.05
p_disc = p10 + p01
share_regress = p10 / p_disc

power = 0.0
for m in range(n + 1):                      # m = number of discordant cases
    b = np.arange(m + 1)                    # b = regressions among them
    p_val = np.minimum(1.0, 2 * binom.cdf(np.minimum(b, m - b), m, 0.5))
    power += binom.pmf(m, n, p_disc) * binom.pmf(b, m, share_regress)[p_val <= alpha].sum()

print(round(power, 4))                      # expected: 0.7754

The result should match 0.7754. If it does not, your two-sided p-value is defined differently from the doubled-tail version used here.

What this changes in practice

  1. Plan with the MDE before you build cases. The MDE is the smallest difference your eval can reliably detect. A quick paired approximation at two-sided α = 0.05 and power 0.80 is MDE ≈ 2.8 × √(discordance / n), where 2.8 ≈ 1.96 + 0.84. Two checks: - n = 200 and discordance 0.10: 2.8 × √(0.10 / 200) ≈ 0.063. Connor's formula gives 0.062. - n = 200 and discordance 0.080: 2.8 × √(0.080 / 200) = 0.056. The walkthrough gives 0.056.

For comparison, two independent groups of 200 cases each can only detect a gain of about 0.100 over 0.80. 2. Freeze one case list. Run A and B on all of it, and keep per-case results keyed by a stable case ID. 3. Analyze the pairs. Report two things: - the 95% interval for pB − pA (Newcombe 1998, Improved confidence intervals for the difference between binomial proportions based on paired data; the default is Newcombe's method 8); - the exact McNemar p-value.

bash shipornot paired-diff --csv results.csv --a-col a --b-col b shipornot mcnemar --csv results.csv --a-col a --b-col b

For a synthetic prompt-tweak example on 200 cases, the results are:

  • B − A = +0.010
  • 95% interval: [−0.030, +0.050]
  • exact McNemar p = 0.8036 4. Read the result against five outcomes: better, worse, not worse by the margin, no difference worth acting on, and not enough evidence. The "not worse" outcome counts only if you declared that question and its margin before the run.

In the example, p is well above 0.05. Its interval runs from −0.030 to +0.050, so it rules out neither "no gain" nor a gain of 0.04 or more. No "not worse" question was declared, so the result is not enough evidence. 5. Do not "add cases and re-test." The first test already spent the full 0.05. Instead: - Treat the 200-case run as a pilot. It gave you a discordance estimate of 0.080. - Size the real test with shipornot n-paired 0.08 0.04 --check-exact. - Build that set from new cases, and test it once at 0.05. - Never ship on the pilot result alone. In the report, state that an earlier 200-case pilot was inconclusive. - If you pool old and new cases instead, label the result exploratory. 6. Do not decide by checking whether A's and B's separate intervals overlap. Overlap does not show "no difference." Non-overlap does indicate a difference, but it is a far stricter test than you need, because it ignores the pairing.

The synthetic data behind that example was generated with a true difference of +0.040. The eval was too small to see it, exactly as the MDE of 0.056 predicted.

When pairing does not help, or does not apply

  • Different case sets for A and B. There are no pairs, so plan with the unpaired formula. shipornot 0.1.0 can size an unpaired design (n-unpaired), but it has no unpaired analysis command.
  • Live-traffic A/B tests. Different users see different variants, so there is no case-level pairing.
  • Clustered cases, such as several questions about the same document. Here the pairs are not independent of each other.

With 5 questions per document and an intra-cluster correlation of 0.2, the design effect is 1.8. Then 200 questions give an effective n of about 111 (200 / 1.8). Adjust n before you plan. - Non-deterministic outputs. If B's result on a case changes from run to run, a single run understates the noise. Decide on reruns before you plan.
